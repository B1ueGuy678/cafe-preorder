# cafe-preorder

到店免排队预点单 —— 独立咖啡店双端（顾客端 / 店员端）最小产品。

> 黑客松题目见工作区对话《从 0 到 1：一个真实用户在用的东西》。
> 按题目阶段推进：需求发现 → 产品定义 → 技术设计 → MVP 垂直切片 → 打磨 → 上线 → 真实复盘。
> 当前进度：**阶段 2（技术设计 + 可运行骨架）已完成**。

## 这是什么

核心机制不是「提前点好、到店取走」——那个形态被调研否定了（步行 15 分钟圈内，
提前做好的意式咖啡会凉，而现场排队只要 3-5 分钟）。

本产品的机制是**按到达时刻倒推下料**：

```
顾客选定到店时刻 8:30，店家配置制作时长 3 分钟
        ↓
下料时刻 = 8:30 − 3min = 8:27
        ↓
顾客 8:30 到店，咖啡刚好做好
```

因此店员端队列**按到店时刻排序**，不是按下单时刻。详见 `docs/PRODUCT.md`。

## 快速开始

```bash
# 1. 安装依赖（本机需带缓存参数，见 SETUP.md）
npm install --cache .npm-cache

# 2. 生成 Prisma Client（已移除 postinstall，需手动执行）
npm run db:generate

# 3. 建库 + 写入种子数据（一家店 + 12 项菜单）
npm run db:push
npm run db:seed

# 4. 启动
npm run dev          # http://localhost:3000
```

- 顾客端：http://localhost:3000
- 店员端：http://localhost:3000/staff

### 店员端口令

店员端会显示顾客手机尾号，因此需要口令进入：

```bash
# .env
STAFF_PASSCODE=改成你自己的口令
```

- **未配置时**：开发环境直接放行（方便本地调试），**生产环境一律拒绝**
- 口令通过 httpOnly cookie 记住会话 12 小时，口令本身永不写入 cookie
- `.env` 不入库；新环境请从 `.env.example` 复制

## 已知技术债（上线前必须处理）

1. **无真实认证**：`/staff` 只有单店口令门，没有账号体系与多角色
2. **轮询而非推送**：前端 4 秒轮询，多顾客时请求量线性增长
3. **无历史订单页**：没有账号体系，顾客无法查看过往订单
4. **SQLite 不适合生产并发写**：生产需切 Postgres
5. **超时取消依赖请求触发**：长时间无人访问时，超时订单会滞留在待接单状态

完整清单见 `docs/ARCHITECTURE.md` 第 8 节。
